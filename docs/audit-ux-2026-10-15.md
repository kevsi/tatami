# Audit UX — Tatami (2026-10-15)

## Périmètre et hypothèses

- **Produit** : Tatami, lecteur desktop de webtoons (Tauri + Next.js), parité
  fonctionnelle avec Kotatsu-Redo. Utilisateur type : lit des webtoons sur PC,
  télécharge pour lire hors ligne.
- **Flux audités** (choisis avec l'humain avant la mesure) : (1) trouver et lire
  un webtoon — accueil → reprise → lecteur ; (2) le découvrir — catalogue →
  langue → source → fiche ; (3) la bibliothèque — téléchargements ; (4) les
  réglages.
- **Méthode** : skill `ux-audit`. Lecture seule — aucun code produit modifié,
  aucune action destructive (aucun téléchargement, aucun favori touché, aucun
  réglage changé). L'app réelle a été pilotée dans sa WebView via CDP
  (`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=9223` + `connectOverCDP`).
- **Hypothèses** : la langue de l'interface est le français (état mesuré :
  `<html lang="fr">`), le thème est sombre (mesuré : `data-apparence="sombre"`),
  et les données sont celles de l'utilisateur (24 lus récemment, 3 favoris,
  7 webtoons téléchargés).

## Findings par flux

### 1. Accueil — reprise d'une lecture

- **F1 — Une liste sans clé dans le lecteur** *(mesuré + code)*.
  Écran : lecteur, bande webtoon. La passe CDP relève **1 erreur console**
  (`Each child in a list should have a unique "key" prop`, `Check the render
  method of Home`) au moment où la reprise ouvre le lecteur. Cause localisée :
  `page.tsx:5679` — `fenetre.map` retourne un **fragment `<>` sans `key`**
  (L5730) ; le `key={p.token}` existe mais sur l'`<img>` *à l'intérieur*
  (L5749), pas sur l'élément du tableau. Sévérité devinée **3** : React ne peut
  pas suivre l'identité des pages quand la fenêtre virtuelle se déplace.
  Preuve : `node .mesures/ux-audit/parcours.cjs`, champ `console.erreurs`.

- **F2 — Contraste insuffisant sur un libellé d'action** *(mesuré)*.
  Écran : accueil, encart « mises à jour ». « Voir le chapitre signalé » :
  `rgb(54, 106, 211)` (accent) sur `rgb(26, 26, 26)` (surface) = **3,45:1**
  pour 12,5 px, sous le seuil AA de 4,5:1. Sévérité devinée **2** (lisibilité
  réduite, pas bloquante). Preuve : `parcours.json`, `contrastesInsuffisants`.
  C'est le **seul** échec de contraste de toute la passe (les autres écrans :
  0).

### 2. Catalogue — découvrir

- **F3 — Une source peut rendre vide sans le dire** *(mesuré)*.
  Écran : source. `BENTOSCAN` a rendu **0 manga, sans erreur affichée**
  (`erreur=null`), le seul indice étant le texte d'aide de la barre d'outils
  (« Clique un webtoon pour voir ses chapitres. »). Le journal moteur montre
  `latest source=BENTOSCAN` répondant en ~2 s à 20:00 (6 mangas), puis 0 à
  20:34 et 21:00. Sévérité devinée **3** : l'utilisateur ne peut pas distinguer
  « cette source n'a rien » de « cette source est cassée ».
  Preuve : `parcours.json` (`sourcesEssayees`), `audit-app.err.log`.

- **F4 — Deux champs de recherche sur le même écran** *(observé)*.
  Écran : catalogue. Le filtre par nom de source (`input.search`) et la
  recherche globale de webtoon (`.recherche-globale`) sont Rendus côte à côte,
  tous deux de type `search`. Sévérité devinée **2** (ambiguïté, pas de blocage).
  À noter : le second est la fonctionnalité ajoutée **cette session**
  (`e316a4d`) — le finding vise leur cohabitation, pas l'une des deux.

- **F5 — Le filtre et son état vide fonctionnent** *(mesuré, positif)*.
  « scan » : 0 → 48 sources affichées (le catalogue était en tuiles de langue
  avant, d'où le 0 initial — artefact de mesure, pas un défaut) ; terme absent :
  « Aucune source à afficher » + « Aucune source ne correspond à « zzzzzaucun » »
  + raccourci « Afficher les 1 source désactivée ». Sévérité **0**.

### 3. Fiche série

- **F6 — 100 chapitres, clés dupliquées** *(mesuré + code)*.
  Écran : fiche « One Piece » (SCANVF). **40 à 100 avertissements console**
  (`Encountered two children with the same key`) selon les rendus. Cause
  localisée : `page.tsx:6051` — `key={c.url}` alors que la source rend des
  **URL de chapitres en double**. Sévérité devinée **3** : React peut attacher
  l'état d'une ligne à une autre, et l'utilisateur voit des doublons dans la
  liste. Preuve : `parcours.json`, `console.erreurs` (étape « Catalogue puis
  source »).

- **F7 — Reprise et métadonnées complètes** *(mesuré, positif)*.
  « Reprendre « One Piece 10 : Désordre à la taverne (en couleurs) » »,
  résumé, statut, auteur, genres, titre alternatif, source. « 1201 chapitres »
  annoncés, ~100 rendus puis « afficher plus » — comportement attendu.
  Sévérité **0**.

### 4. Lecteur

- **F8 — Le flux principal fonctionne** *(mesuré, positif)*.
  Reprise → image décodée 720×4096, compteur `1 / 17`, barre complète
  (← Chapitres, Signet, ← →, zoom 60 %, sélecteur de chapitre, Page 1 / 17),
  défilement clavier `scrollTop 0 → 85` sur le conteneur `.webtoon`, sortie par
  Échap effective. Sévérité **0**.

- **F9 — Suspicion visuelle infirmée par la mesure** *(mesuré)*.
  La capture montrait du noir au-dessus de la page 1. Mesure : `videAuDessus: 0`
  — ce noir fait partie de l'image. **Pas un défaut.** Consigné parce qu'une
  suspicion non mesurée serait devenue un finding fantôme.

### 5. Téléchargements et réglages

- **F10 — Bibliothèque riche et lisible** *(mesuré, positif)*.
  7 webtoons, 20 chapitres, 86,0 Mo sur le disque, « 2 À compléter », carte
  « Annoying Alice ». Sévérité **0**.
- **F11 — Réglages complets** *(observé, positif)*.
  Contenu affiché (classification, avec note explicative), catégories de favoris
  (couleurs, ordre, suppression), apparence. Sévérité **0**.
- **F12 —focus clavier sain** *(mesuré, positif)*.
  12 arrêts de tabulation, **0 sans anneau de focus visible**. Sévérité **0**.

## Transversal

- **F13 — Des fenêtres de vérification s'ouvrent et restent** *(observé)*.
  Pendant l'audit, le navigateur de la WebView porte en permanence 2 à 5 cibles
  : l'app, plus une page `readcomicsonline.ru/comic-list` titrée
  « Un instant… » et une iframe Cloudflare Turnstile. Le journal montre
  `latest source=READCOMICSONLINE` → `CHALLENGE_REQUIRED` → transport →
  « challenge non résolu en 60 s ». Sévérité devinée **3** : une fenêtre
  mystère apparaît sans que l'utilisateur l'ait demandée, et rien à l'écran ne
  dit qu'elle vient du planificateur. La mesure ne dit pas **qui** l'a déclenchée
  au démarrage (le premier tick du planificateur est immédiat, cf. §14) — à
  confirmer avant de corriger.

## Harness (défauts de l'instrument, pas du produit)

- **H1 — Le bulbe rouge « N Issues × »** n'appartient pas à l'app : la chaîne
  « Issues » est absente du code (`grep "Issue"` sur `app/` = 0 résultat) et son
  compte suit exactement les erreurs console (1, puis 9). C'est le compteur
  d'anomalies injecté par le navigateur. Il recouvre le libellé « Apparence »
  dans une capture — à ne pas corriger dans le produit.
- **H2 — Le binaire debug exige le serveur de dev.** Premier run :
  `chrome-error://chromewebdata/` et `ERR_CONNECTION_REFUSED`, parce que
  `tauri.conf.json` porte `devUrl: http://localhost:3001` et que `next dev` ne
  tournait pas. Fait d'outillage, pas défaut produit.
- **H3 — Erreurs de mes propre instrument, corrigées puis divulguées** :
  sélecteur `.manga` attrapant les squelettes (même classe que les vraies
  cartes) ; `page.fill('input.search')` visant la recherche globale au lieu du
  filtre ; `pages[0]` visant la page Cloudflare au lieu de l'app ; `scrollTop`
  mesuré sur `.reader` au lieu de `.webtoon` ; compte d'`<img>` sans `alt`
  gonflé par des commentaires. Chacune a été corrigée dans le script et la
  mesure rejouée — les chiffres cités sont ceux d'après correction.

## Probablement sain

- Les 2 tokens morts (`--bg-elev`, `--shadow-sm`) : dette cosmétique, sans
  effet d'affichage.
- Les 7 `<button>` sans classe : héritent du contexte, pas de doublon de style
  observé.
- Les 38 clés d'état vide / 18 de chargement / 74 d'erreur : la plupart sont
  branchées et visibles dans les captures ; l'inventaire ne dit pas lesquelles
  sont inutilisées — `pnpm i18n:check` verrouille déjà l'inverse (aucune clé
  morte), donc une clé déclarée est une clé utilisée.
- Les bandes noires autour de la bande webtoon : inhérentes à la lecture
  verticale (mesuré : la bande occupe toute la largeur, 1 366 px).
- « 1201 chapitres » avec ~100 rendus : pagination voulue.

## Priorités proposées

L'humain a donné le cadre (« UX fonctionnelle d'abord »), donc une proposition
est possible — **elle reste une proposition**, à valider par quelqu'un qui
connaît les plans produit :

1. **F6 + F1 (clés React)** — même fichier, même famille, coût faible. Une
   série à 100+ chapitres est le cas courant, pas un cas limite.
2. **F3 (source vide muette)** — un message honnête (« cette source n'a rien
   renvoyé ») distingue une panne d'un catalogue vide ; c'est le défaut que
   l'utilisateur ne peut pas diagnostiquer seul.
3. **F2 (contraste 3,45:1)** — un token à ajuster, précédent existant
   (`--accent-dim-texte`).
4. **F4 (deux recherches)** — décision d'affichage, pas un correctif.
5. **F13 (fenêtres Cloudflare)** — comprendre qui les déclenche avant d'agir.

## Comment rejouer

```powershell
# 1. Serveur de dev (le binaire debug le exige) + app avec CDP
cd apps\desktop ; pnpm dev            # port 3001
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9223"
Start-Process apps\desktop\src-tauri\target\debug\tatami-desktop.exe -WindowStyle Hidden

# 2. Inventaire puis parcours (sortie : parcours.json + captures/)
node .mesures\ux-audit\inventaire.mjs
node .mesures\ux-audit\parcours.cjs
```

Les captures sont dans `.mesures/ux-audit/captures/` (14 fichiers), le détail
mesuré dans `.mesures/ux-audit/parcours.json`. **Les scripts ne sont pas
commités** (`.mesures/` est dans `.gitignore`) : ils restent sur le poste de
mesure ; le présent rapport dit ce que chacun compte, ce qui permet de le
réécrire. Les findings, eux, sont tous cités avec leur preuve pour rester
vérifiables sans les scripts.
